1. JUSTIFICACIÓN DEL ALGORITMO SELECCIONADO
================================================================================

ALGORITMO: Perceptrón Multicapa (MLP)

FUNDAMENTO:
El Perceptrón Multicapa es una red neuronal artificial feedforward que consiste en:
- Una capa de entrada que recibe las features
- Una o más capas ocultas con neuronas interconectadas
- Una capa de salida que produce las predicciones

Proceso de aprendizaje mediante:
1. Forward propagation: Cálculo de activaciones hacia adelante
2. Cálculo de error: Comparación con etiquetas reales
3. Backpropagation: Propagación de error hacia atrás
4. Actualización de pesos: Optimización mediante gradiente descendente

JUSTIFICACIÓN DE LA SELECCIÓN:
✓ Clasificación multiclase natural con softmax
✓ Captura relaciones no lineales mediante capas ocultas
✓ Aproximador universal de funciones continuas
✓ Implementable completamente en C sin dependencias complejas
✓ Escalable a datasets grandes (217K+ muestras)
✓ Balance entre complejidad y desempeño

VENTAJAS SOBRE ALTERNATIVAS:
- vs KNN: O(1) en predicción vs O(n), más eficiente
- vs Regresión Logística: Captura no linealidades
- vs Árbol de Decisión: Menos propenso a overfitting
- vs Naive Bayes: No asume independencia condicional

ARQUITECTURA IMPLEMENTADA:
- Input: 10 features
- Hidden 1: 20 neuronas (ReLU)
- Hidden 2: 10 neuronas (ReLU)
- Output: 5 neuronas (Softmax)
- Total parámetros: 10×20 + 20×10 + 10×5 = 450 parámetros

2.1. ESTRUCTURAS PRINCIPALES
--------------------------------------------------------------------------------

DataPoint: Representa una muestra individual
- double* features: Array de valores de entrada
- int label: Clase de la muestra (0-4)

Dataset: Colección de datos
- DataPoint* data: Array de muestras
- int num_samples, num_features, num_classes
- double* feature_means, feature_stds: Para normalización

Layer: Representa una capa de la red
- double** weights: Matriz de pesos [neuronas][inputs]
- double* biases, outputs, pre_activation, deltas
- char activation[16]: Tipo de función de activación

MLP: Red neuronal completa
- Layer** layers: Array de capas
- int num_layers
- double learning_rate, momentum, weight_decay
- Velocities para momentum

2.2. MÓDULOS IMPLEMENTADOS
--------------------------------------------------------------------------------

1. activation.c: Funciones ReLU, Sigmoid, Tanh, Softmax + derivadas
2. data_utils.c: Carga, normalización, shuffle, split de datos
3. mlp_core.c: Creación de capas, inicialización de pesos (Xavier/He)
4. forward.c: Propagación hacia adelante capa por capa
5. backward.c: Backpropagation y cálculo de gradientes
6. optimizer.c: SGD con momentum y regularización L2
7. training.c: Loop de entrenamiento con early stopping
8. prediction.c: Inferencia y predicción batch
9. metrics.c: Accuracy, balanced accuracy, F1-score, confusion matrix

3.1. FRAGMENTOS DE CÓDIGO CLAVE
--------------------------------------------------------------------------------

INICIALIZACIÓN DE PESOS (He para ReLU):
```c
double scale = sqrt(2.0 / layer->num_inputs);
for (int i = 0; i < num_neurons; i++) {
    for (int j = 0; j < num_inputs; j++) {
        double r = ((double)rand() / RAND_MAX) * 2.0 - 1.0;
        layer->weights[i][j] = r * scale;
    }
}
```

FORWARD PASS CON RELU:
```c
for (int i = 0; i < layer->num_neurons; i++) {
    layer->pre_activation[i] = layer->biases[i];
    for (int j = 0; j < layer->num_inputs; j++) {
        layer->pre_activation[i] += layer->weights[i][j] * input[j];
    }
    layer->outputs[i] = layer->pre_activation[i] > 0 ? 
                        layer->pre_activation[i] : 0;  // ReLU
}
```

SOFTMAX NUMERICAMENTE ESTABLE:
```c
double max_val = input[0];
for (int i = 1; i < size; i++) {
    if (input[i] > max_val) max_val = input[i];
}
double sum = 0.0;
for (int i = 0; i < size; i++) {
    output[i] = exp(input[i] - max_val);  // Resta max para estabilidad
    sum += output[i];
}
for (int i = 0; i < size; i++) {
    output[i] /= sum;
}
```

BACKPROPAGATION - DELTA OUTPUT:
```c
for (int i = 0; i < output_layer->num_neurons; i++) {
    if (i == true_label) {
        output_layer->deltas[i] = output_layer->outputs[i] - 1.0;
    } else {
        output_layer->deltas[i] = output_layer->outputs[i];
    }
}
```

BACKPROPAGATION - CAPAS OCULTAS:
```c
for (int i = 0; i < current->num_neurons; i++) {
    double sum = 0.0;
    for (int j = 0; j < next->num_neurons; j++) {
        sum += next->weights[j][i] * next->deltas[j];
    }
    double derivative = (current->outputs[i] > 0) ? 1.0 : 0.0;  // ReLU'
    current->deltas[i] = sum * derivative;
}
```

ACTUALIZACIÓN CON MOMENTUM:
```c
for (int i = 0; i < layer->num_neurons; i++) {
    for (int j = 0; j < layer->num_inputs; j++) {
        double grad = layer->weight_grads[i][j] / batch_size;
        double reg = mlp->weight_decay * layer->weights[i][j];
        mlp->velocity_w[l][i][j] = mlp->momentum * mlp->velocity_w[l][i][j] +
                                   mlp->learning_rate * (grad + reg);
        layer->weights[i][j] -= mlp->velocity_w[l][i][j];
    }
}
```

5. ANÁLISIS DE LIMITACIONES
================================================================================

5.1. LIMITACIONES DEL ALGORITMO MLP
--------------------------------------------------------------------------------

⚠ DESBALANCEO DE CLASES:
- Clase B+ (1.35% de datos) difícil de predecir (F1=0.67)
- Clases mayoritarias dominan el aprendizaje
- Solución: SMOTE, class weights, focal loss

⚠ ARQUITECTURA FIJA:
- Número de capas y neuronas predefinido
- Exploración de hiperparámetros requiere recompilación
- Solución: Parámetros de línea de comandos o archivo config

⚠ RIESGO DE MÍNIMOS LOCALES:
- SGD puede quedar atrapado en óptimos locales
- Solución: Múltiples inicializaciones, optimizadores adaptativos (Adam)

⚠ SENSIBILIDAD A INICIALIZACIÓN:
- Pesos mal inicializados pueden impedir convergencia
- Mitigado: Inicialización He/Xavier

⚠ INTERPRETABILIDAD:
- Menos interpretable que árboles de decisión o regresión logística
- Difícil explicar por qué se tomó una decisión

5.2. LIMITACIONES DE LA IMPLEMENTACIÓN EN C
--------------------------------------------------------------------------------

⚠ SIN TÉCNICAS AVANZADAS:
- No implementa: Dropout, Batch Normalization, Data Augmentation
- No soporta: Adam, RMSprop, Learning rate scheduling complejo
- No incluye: Validación cruzada, Grid search

⚠ ARQUITECTURA NO DINÁMICA:
- Cambiar arquitectura requiere modificar código
- No soporta arquitecturas arbitrarias en tiempo de ejecución

⚠ SIN PARALELIZACIÓN:
- No usa OpenMP o pthreads
- Podría acelerar 2-4x en CPUs multi-core

⚠ GESTIÓN MANUAL DE MEMORIA:
- Riesgo de memory leaks si no se maneja correctamente
- Requiere disciplina en free() de todas las estructuras

⚠ SIN VISUALIZACIÓN:
- No genera gráficos de convergencia
- No logging detallado para debugging

5.3. LIMITACIONES DEL DATASET SINTÉTICO
--------------------------------------------------------------------------------

⚠ DATOS GENERADOS:
- No captura toda la complejidad del problema real
- Correlaciones simplificadas entre features y labels
- Distribuciones idealizadas

⚠ TAMAÑO REDUCIDO:
- 50K muestras vs 217K del dataset original
- Menos diversidad de patrones
